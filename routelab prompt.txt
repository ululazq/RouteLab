# RouteLab — Cycling Route Intelligence Platform

Saya ingin membangun aplikasi Android bernama **RouteLab**.

## 1. Konsep Utama

**RouteLab adalah aplikasi untuk menganalisis dan memahami rute sepeda sebelum pengguna melakukan perjalanan.**

RouteLab bukan sekadar aplikasi navigasi atau route planner.

Tujuan utamanya adalah menjawab pertanyaan:

> **“Kalau saya melewati rute ini, sebenarnya perjalanan saya akan seperti apa?”**

Pengguna memasukkan atau membuat sebuah rute sepeda, kemudian RouteLab melakukan analisis terhadap seluruh perjalanan dan mengubah data mentah dari peta menjadi informasi yang mudah dipahami.

Tagline konsep:

> **RouteLab — Analyze the Ride Before You Ride.**

Konsep produknya adalah:

**ROUTE → ANALYZE → UNDERSTAND → PLAN → RIDE**

---

# 2. Masalah yang Ingin Diselesaikan

Saat ini seorang pesepeda biasanya hanya melihat:

* jarak
* estimasi waktu
* elevation profile

Namun informasi tersebut belum cukup untuk memahami sebuah perjalanan.

Misalnya, dua rute sama-sama memiliki jarak 70 km dan elevation gain 500 m, tetapi pengalaman berkendaranya bisa sangat berbeda karena:

* jenis jalan berbeda
* jumlah tanjakan berbeda
* gradient berbeda
* permukaan jalan berbeda
* banyak persimpangan
* banyak jalan besar
* traffic berbeda
* tanjakan terkonsentrasi di satu bagian
* kondisi rute bagian akhir lebih berat
* terdapat sedikit tempat untuk berhenti atau melakukan fueling

RouteLab harus mengubah informasi tersebut menjadi **route intelligence**.

---

# 3. Core Feature — Route Analyzer

Pengguna dapat memasukkan sebuah rute menggunakan salah satu metode yang tersedia, misalnya:

* membuat rute pada peta
* import GPX
* memasukkan route dari sumber eksternal
* membuka route yang sebelumnya telah disimpan

Setelah route tersedia, pengguna dapat menjalankan:

> **Analyze Route**

RouteLab kemudian menganalisis rute tersebut.

# 6. Route Segmentation

RouteLab harus membagi rute menjadi beberapa segmen yang memiliki karakteristik berbeda.

Contoh:

**Segment 1 — KM 0–12**

Flat / urban

**Segment 2 — KM 12–18**

Rolling

**Segment 3 — KM 18–23**

Major Climb

**Segment 4 — KM 23–35**

Descending / Flat

**Segment 5 — KM 35–48**

Rolling

Tujuannya agar pengguna dapat memahami perjalanan berdasarkan bagian-bagiannya, bukan hanya melihat satu garis panjang di peta.

---

# 7. Difficulty Analysis

RouteLab harus memberikan analisis tingkat kesulitan rute berdasarkan data objektif.

Jangan hanya menggunakan jarak sebagai indikator.

Pertimbangkan faktor seperti:

* distance
* elevation gain
* elevation gain per kilometer
* gradient
* jumlah tanjakan
* panjang tanjakan
* steepness
* terrain distribution
* road surface
* route complexity

Hasilnya dapat berupa kategori seperti:

* Easy
* Moderate
* Challenging
* Very Challenging

Namun kategori tersebut harus berasal dari sistem scoring yang transparan dan dapat dikembangkan kemudian.

Tampilkan juga alasan di balik tingkat kesulitan.

Contoh:

> **Challenging**
>
> Primarily caused by 3 major climbs in the second half of the route and approximately 920 m total elevation gain.

---

# 8. COT / Target Time Planning

Pengguna dapat menentukan target perjalanan.

Contoh:

**Distance:** 100 km
**Target COT:** 6 hours

RouteLab kemudian menghitung strategi perjalanan.

Jangan hanya menghitung:

> 100 km / 6 hours = 16.7 km/h

Karena kondisi rute tidak selalu sama.

RouteLab harus mempertimbangkan:

* elevation
* gradient
* climbing
* descending
* flat sections
* expected stops
* rest
* fueling
* route difficulty

Kemudian membagi rute menjadi beberapa segmen dan memberikan target pace yang masuk akal.

Contoh:

| Segment |  Distance | Terrain         | Target   |
| ------- | --------: | --------------- | -------- |
| 1       |   0–20 km | Flat            | Maintain |
| 2       |  20–32 km | Rolling         | Moderate |
| 3       |  32–40 km | Climbing        | Conserve |
| 4       |  40–65 km | Descending/Flat | Recover  |
| 5       |  65–82 km | Rolling         | Maintain |
| 6       | 82–100 km | Mixed           | Adjust   |

>

>

# 18. Product Philosophy

RouteLab harus mengikuti prinsip:

### Data First

Gunakan data nyata jika tersedia.

### No Fake Precision

Jangan memberikan angka yang terlihat akurat jika sumber datanya tidak cukup.

### Explain the Analysis

Jika RouteLab mengatakan sebuah rute “Challenging”, pengguna harus bisa mengetahui alasannya.

### Actionable Information

Jangan hanya menampilkan:

> Elevation Gain: 840 m

# 21. Build & CI/CD — GitHub Actions

RouteLab harus dirancang sejak awal agar seluruh proses build dan validasi aplikasi dapat dijalankan menggunakan **GitHub Actions**.

Tujuan utamanya adalah:

> **Developer melakukan push ke GitHub → GitHub Actions melakukan validation, testing, build, dan menghasilkan Android artifact secara otomatis.**

Local development tetap dapat digunakan, tetapi project **tidak boleh bergantung pada konfigurasi khusus di komputer developer** agar dapat dibuild.

---

## CI/CD Requirements

Gunakan GitHub Actions sebagai automated CI/CD pipeline.

Minimal pipeline harus melakukan:

1. Checkout repository
2. Setup Java/JDK yang sesuai
3. Setup Android SDK
4. Restore Gradle cache
5. Validate Gradle configuration
6. Run lint
7. Run unit tests
8. Build Android application
9. Upload build artifact

Pipeline harus gagal jika:

* compilation error
* unit test gagal
* lint memiliki error yang dikonfigurasi sebagai blocking
* Gradle build gagal
* dependency/configuration bermasalah

---

## Branch Strategy

Siapkan workflow untuk minimal:

### Pull Request

Saat Pull Request dibuat atau di-update:

```text
Pull Request
     ↓
GitHub Actions
     ↓
Lint
     ↓
Unit Test
     ↓
Build
     ↓
Pass / Fail
```

Tujuannya memastikan code yang akan di-merge sudah dapat dikompilasi dan lolos automated checks.

### Main Branch

Saat perubahan masuk ke `main`:

```text
Push / Merge to main
        ↓
GitHub Actions
        ↓
Test
        ↓
Build
        ↓
Generate APK
        ↓
Upload Artifact
```
